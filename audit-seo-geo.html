Problèmes critiques — Priorité P0

Ces 3 points doivent être corrigés en premier. Ils bloquent ou dégradent significativement l'indexation et la visibilité dans les moteurs classiques et les moteurs IA.

❌
Aucune donnée structurée Schema.org / JSON-LD
Critique SEO + GEO

Le site ne contient aucun bloc <script type="application/ld+json">. C'est le problème le plus grave : Google Rich Results, Knowledge Panel, et tous les moteurs IA (ChatGPT, Perplexity, Gemini, Claude) utilisent les données structurées pour comprendre qui tu es et ce que tu fais.

Sans schéma Person, une requête comme "product owner designer Belgium freelance" ou "Hamza Khadri" sur un moteur IA ne peut pas extraire d'entité fiable depuis ton site.

Solution minimum à implémenter dans <head> :

<script type="application/ld+json"> { "@context": "https://schema.org", "@type": "Person", "name": "Hamza Khadri", "jobTitle": "Product Owner, Designer & Builder", "url": "https://hamzakhadri.com", "email": "Hamza.Khadri@outlook.com", "address": { "@type": "PostalAddress", "addressCountry": "BE", "addressLocality": "Mont-Saint-Guibert" }, "sameAs": [ "https://www.linkedin.com/in/hamzakhadri", "https://github.com/hamza-k", "https://dribbble.com/hamza-k" ], "worksFor": { "@type": "Organization", "name": "The Maul" }, "knowsAbout": ["Product Management", "UX Design", "No-code", "AI Integration", "Supabase", "Lovable"] } </script>
❌
Pas de sitemap.xml — réponse 404
Critique SEO

La requête GET /sitemap.xml retourne un 404. Google et Bing utilisent le sitemap pour découvrir et prioriser les pages à indexer. Sans lui, le crawl repose entièrement sur les liens internes — insuffisant pour un single-page site.

Le sitemap doit aussi être déclaré dans robots.txt. Créer le fichier sitemap.xml à la racine :

<?xml version="1.0" encoding="UTF-8"?> <urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9"> <url> <loc>https://hamzakhadri.com/</loc> <lastmod>2026-06-22</lastmod> <changefreq>monthly</changefreq> <priority>1.0</priority> </url> </urlset>
❌
Pas de robots.txt — réponse 404
Critique SEO

La requête GET /robots.txt retourne un 404. Sans ce fichier, les crawlers (dont les bots IA de Common Crawl, GPTBot, ClaudeBot, PerplexityBot) n'ont aucune directive.

Créer le fichier robots.txt à la racine :

User-agent: * Allow: / User-agent: GPTBot Allow: / User-agent: ClaudeBot Allow: / User-agent: PerplexityBot Allow: / Sitemap: https://hamzakhadri.com/sitemap.xml

Note : l'autorisation explicite des bots IA (GPTBot, ClaudeBot, PerplexityBot) est une bonne pratique GEO — elle maximise les chances d'être indexé par leurs bases de connaissances.

Problèmes importants — Priorité P1

⚠️
H1 dynamique — contenu cassé pour les crawlers
ImportantSEO

Le H1 contient un typewriter animé en React. Au moment du crawl, Playwright capture le texte suivant : "Ibuild|products." — la barre de caret | est incluse dans le DOM et l'espace entre "I" et le mot animé est absent. Google indexe ce texte corrompu.

Solution : Ajouter un aria-label statique sur le H1 qui contient le texte complet optimisé :

<h1 aria-label="Hamza Khadri — I build, lead and ship products." ...>
⚠️
Attribut lang="en" statique — non mis à jour au switch FR
ImportantSEO

Le site propose un switch EN/FR fonctionnel, mais <html lang="en"> ne change jamais côté DOM. Quand l'utilisateur passe en français, la langue déclarée reste l'anglais — mauvais pour le SEO francophone et les lecteurs d'écran.

Solution : Dans app.jsx, appeler document.documentElement.lang = lang à chaque changement de langue.

⚠️
Aucune balise hreflang pour le contenu bilingue EN/FR
ImportantSEO

Le site sert du contenu EN et FR sur la même URL sans directives hreflang. Les moteurs ne savent pas quelle langue cibler par région (BE-FR, BE-NL, etc.). Ajouter dans <head> :

<link rel="alternate" hreflang="en" href="https://hamzakhadri.com/" /> <link rel="alternate" hreflang="fr" href="https://hamzakhadri.com/?lang=fr" /> <link rel="alternate" hreflang="x-default" href="https://hamzakhadri.com/" />
⚠️
Aucune image avec loading="lazy" — 9 images chargées immédiatement
ImportantCore Web Vitals

Les 9 images projet ont toutes loading="auto". Les images hors-viewport initiale (8 images projet sur 9) chargent immédiatement, bloquant la bande passante disponible pour le LCP.

Solution : Ajouter loading="lazy" sur toutes les images projet dans components/work.jsx. Garder loading="eager" (ou pas d'attribut) uniquement sur la photo hero.

⚠️
Pas de preload sur l'image LCP (photo hero)
ImportantLCP / Core Web Vitals

assets/hamza-photo.png est l'élément LCP (Largest Contentful Paint) probable, mais n'est pas préchargé. Le navigateur ne la découvre qu'en parsant le JS/JSX. Ajouter dans <head>, avant les scripts :

<link rel="preload" as="image" href="assets/hamza-photo.png" />
⚠️
React en mode développement + transpilation Babel dans le navigateur
ImportantPerformance

Le site charge react.development.js (non minifié, ~1MB) et transpile le JSX via @babel/standalone dans le navigateur. C'est 2 à 3 fois plus lent que servir des fichiers pré-compilés. Impact direct sur le FCP, LCP et le score Core Web Vitals.

Solution : Passer à Vite (ou tout bundler) pour pré-compiler et minifier. Ou à minima charger react.production.min.js et react-dom.production.min.js.

⚠️
Contenu total : ~800 mots — thin content
ImportantSEO Contenu

Le site ne contient que ~800 mots indexables. Google considère les portfolios single-page comme "thin content" — peu de signal de pertinence thématique. Pour un profil Product Owner / Designer / Builder, la concurrence est forte.

Solution : Créer des URLs dédiées par projet (ex. /partenamut-prevention) avec les descriptions complètes déjà rédigées dans content.js. Elles existent mais sont enfermées dans des modales.

⚠️
Pas d'URL unique par projet — case studies invisibles
ImportantSEO Contenu

Les 8 case studies (Partenamut, Veleo, Gravaubel, etc.) s'ouvrent en modal sur /#. Ces pages ne sont jamais indexées : ni /partenamut-prevention, ni /#partenamut ne sont crawlés. Le contenu projet le plus riche du site est complètement invisible pour Google.

Ces descriptions existent déjà dans content.js — il suffit de les rendre accessibles via un routing client-side ou des pages statiques.

GEO — Generative Engine Optimization

Le GEO est l'optimisation pour être cité, référencé et recommandé par les moteurs IA génératifs — ChatGPT, Perplexity, Gemini, Claude, Bing Copilot. Contrairement au SEO classique qui optimise pour le ranking, le GEO optimise pour l'extraction d'entités et la fiabilité des réponses générées. Les moteurs IA privilégient les sites qui fournissent des faits structurés, des entités claires et du contenu dense et vérifiable.

Problèmes critiques GEO P0
❌
Aucune entité machine-lisible — le site est invisible pour les moteurs IA
GEO Critique

Si un utilisateur demande à ChatGPT ou Perplexity "qui est Hamza Khadri ?", ou "product owner designer freelance Belgique", le site ne fournit aucune entité structurée exploitable. Les moteurs IA ne peuvent pas construire de réponse fiable à partir d'un site sans JSON-LD.

La priorité est d'implémenter le schéma Person décrit en page 3, complété d'un schéma WebSite :

{ "@context": "https://schema.org", "@type": "WebSite", "name": "Hamza Khadri — Portfolio", "url": "https://hamzakhadri.com", "description": "Portfolio de Hamza Khadri, Product Owner, Designer et Builder basé en Belgique.", "author": { "@type": "Person", "name": "Hamza Khadri" } }
❌
Le contenu est du marketing copy, pas du contenu factuel citable
GEO Critique

Les moteurs IA citent des pages qui contiennent des faits concrets et vérifiables. Le site contient du copy engageant mais peu de données extraibles :

❌ Formulation actuelle (copy)✅ Formulation GEO-optimisée (factuelle)
"I own the product end-to-end""Product Owner sur 8 projets livrés entre 2025 et 2026 en Belgique"
"Many projects, many problems solved""15+ produits livrés, dont Partenamut, Veleo, Velox, LAM-MotionLabs"
"Discovery before pixels""17 tests utilisateurs modérés conduits pour Partenamut Prevention (2026)"
"5+ Years in product""5 ans d'expérience produit, depuis 2021, basé à Mont-Saint-Guibert, Belgique"

Les chiffres et faits existent dans le contenu des case studies — il faut les remonter dans des paragraphes indexables.

Améliorations GEO importantes P1–P2
⚠️
Pas de section FAQ — format le plus cité par les moteurs IA
GEO

Les FAQ avec schéma FAQPage sont le format le plus souvent cité dans les réponses ChatGPT et Perplexity. Une section "Questions sur mes services" (coût, délai, process, disponibilité) avec FAQPage JSON-LD augmenterait significativement la surface de citation.

Exemples de questions pertinentes : "Travailles-tu en remote ?", "Quels types de produits as-tu livrés ?", "Quelle est ta disponibilité en 2026 ?"

⚠️
Témoignages sans schéma Review — preuve sociale non structurée
GEO

Les deux témoignages (Nicolas Streel, CMO The Maul ; Simon Moreau, PM Line-out) sont riches mais non structurés. Ajouter un schéma Review ou Person sur chaque auteur permettrait aux moteurs IA de les utiliser comme signal de crédibilité.

⚠️
Bots IA non mentionnés dans robots.txt — indexation GEO non maîtrisée
GEO

Outre le problème d'absence de robots.txt (P0), les bots des moteurs IA ont des identifiants spécifiques : GPTBot, ClaudeBot, PerplexityBot, Google-Extended. Sans directives explicites, leur comportement est imprévisible. Le fichier robots.txt recommandé en page 3 couvre ce point.

ℹ️
Projets sans schéma CreativeWork — œuvres non associées à l'entité
GEO P2

Chacun des 8 projets mériterait un schéma CreativeWork ou SoftwareApplication lié à l'entité Person. Cela permettrait aux moteurs IA d'associer "Veleo", "Partenamut", "Velox" à Hamza Khadri dans leurs bases de connaissances.

Résumé exécutif

Le portfolio de Hamza Khadri dispose de bases SEO solides (meta tags, OG, favicons, responsive) mais manque des trois fondamentaux qui permettraient une visibilité réelle : données structurées, sitemap et robots.txt. Le site est actuellement quasi-invisible pour les moteurs IA génératifs (ChatGPT, Perplexity, Gemini) faute d'entité machine-lisible. Les P0 sont tous implémentables en moins d'une heure et auraient un impact immédiat. Sur le moyen terme, transformer les modales projet en pages dédiées indexables multiplierait par 8 la surface de contenu crawlable — c'est le levier SEO le plus puissant disponible dans ce projet.
